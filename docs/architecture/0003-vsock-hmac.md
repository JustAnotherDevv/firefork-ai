# 0003. HMAC-signed vsock IPC with canonical JSON

- **Status:** Accepted
- **Date:** 2026-05-26

## Context

Every fork runs an in-guest agent (`agent.py`) listening on AF_VSOCK
port 1234. The host orchestrator drives the agent via a UNIX-domain
socket (`<workdir>/vsock.sock_1234` once Firecracker maps the port) to:

- `ping` -- confirm the agent is responsive
- `exec` -- run a shell command or argv inside the guest
- `read_file` / `write_file` -- manipulate guest filesystem state

Without authentication, anything on the host with read access to the
UDS can drive the guest. Pre-jailer that meant any process on the
host; post-jailer it's narrower but still includes anything the
orchestrator's uid can reach. A snapshot served from an untrusted
bucket would inherit no per-instance secret, so secret-on-the-wire
schemes are out.

## Decision

Every non-`ping` command is signed with HMAC-SHA256 using a per-boot
random shared secret generated by the agent at startup. The agent
returns the secret in its `ping` reply (bootstrap) and the host caches
it locally in the template registry (mode 0600). The secret is never
uploaded to remote storage; remote snapshots are restored on a host
that generates a fresh secret on first boot.

Signing uses canonical JSON: keys sorted lexicographically, no
whitespace, `ensure_ascii` semantics matching
`json.dumps(sort_keys=True, separators=(',', ':'))` byte-for-byte. The
Go encoder drives `SetEscapeHTML(false)` to match Python.

Wire format:

```
host -> guest:  {"auth":"<hex>","cmd":"exec","sh":"id"}\n
guest -> host:  {"stdout":"uid=0(root) ...\n","stderr":"","exit_code":0}\n
```

The auth tag is computed over the message with the `auth` field
removed (then re-added). This prevents an attacker who sees one signed
message from replaying it with a different auth payload.

## Alternatives considered

- **TLS over vsock.** Requires PKI infrastructure inside the guest for
  per-instance certs. Heavy. The trust model (single-tenant, trusted
  operator) doesn't need TLS; HMAC is sufficient against the actual
  threats (host neighbours, bucket attackers).
- **PKI with SSH-style host keys.** Same problem as TLS; pubkey
  distribution + revocation overhead for a primitive that only needs
  proof-of-snapshot.
- **No auth (legacy mode).** Acceptable for `ping` only -- that's the
  bootstrap channel and exposes nothing sensitive. Defaulted off for
  all other commands.
- **Per-message nonces.** Considered for replay protection. Rejected
  because vsock is point-to-point and the agent kills the connection
  after each command; no useful replay surface within a fork.

## Consequences

- **Positive:** A compromised neighbour process on the host that gains
  read access to a fork's `vsock.sock` cannot drive it without also
  reading the registry file (which is 0o600).
- **Positive:** Per-boot secrets mean a leaked secret affects exactly
  one fork generation. Forks restarted on a different host get fresh
  secrets.
- **Positive:** Canonical JSON makes the Go <-> Python signature
  byte-identical and debuggable.
- **Negative:** Plain ASCII required everywhere. Em-dashes, smart
  quotes, etc., break HMAC because Go canonical JSON emits raw UTF-8
  while Python's default is `ensure_ascii=True`.
- **Negative:** Nested objects in commands aren't sorted recursively;
  only the top level. Today's commands are all flat (`cmd`, `argv`,
  `sh`, `timeout`, `text`, `src`, `path`, `content`). Recursion stays
  a TODO until a nested object is needed.
- **Negative:** First-boot `ping` is unauthenticated. Acceptable
  because the only payload is the secret itself; the agent generates
  a fresh one every restart.
